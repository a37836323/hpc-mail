# HPC Mail Design System

> 本文件是新版 HPC Mail 的全局设计基线。页面级规则位于 `pages/`，页面规则与本文件冲突时以页面规则为准。

## 1. 产品气质

HPC Mail 是一个面向个人管理员的多域名邮件工作台，不是营销落地页，也不是传统后台模板。

设计关键词：

- 内容优先
- 安静、可靠、清晰
- 桌面高效率，移动端完整可用
- 多域名能力可见但不过度暴露技术细节
- 克制的层级与动效，不使用装饰性视差、厚重渐变或大面积玻璃拟态

## 2. 前端组件体系

当前已实现的新版界面采用以下组合：

- Vue 3 + Vite：保留现有技术栈。
- 原生 CSS 自定义属性：负责布局、响应式和设计令牌；项目没有引入 Tailwind。
- 项目内 `components/ui`：维护 Button、IconButton、FormField 等轻量组件；项目没有引入 shadcn-vue。
- Reka UI：提供认证绑定和写信 Dialog 等可访问性基础能力。
- Lucide Vue：新版主要功能图标来源；既有 Iconify 依赖仍为兼容保留。
- TinyMCE：保留既有正文编辑能力，并由新版写信界面重新组织。
- Pinia、Vue Router、Axios、Dexie：继续保留。

迁移规则：

1. 优先使用项目内 UI 组件和 Reka UI；复杂表格、标签输入、日期控件等继续复用 Element Plus。
2. Element Plus 的全局变量映射到同一 CSS 设计令牌，保证渐进迁移期间视觉一致。
3. 应用外壳、认证页、写信页、邮件视图和管理视图均已套用新版布局与令牌。
4. 组件源码统一放在 `mail-vue/src/components/ui/`，业务组件放在 `mail-vue/src/components/mail/`。

## 3. 全局布局

### 桌面端（>= 1024px）

- 应用侧边栏：240px，可折叠至 72px。
- 邮件列表：360px 至 420px，可调整宽度。
- 邮件详情：填满剩余空间。
- 写信从应用内以大型 Dialog 打开；当前没有声明独立 `/compose` 深链路。
- 顶部不再保留贯穿全站的厚重 Header；搜索、主题、账户入口进入内容工具栏或侧边栏底部。

### 平板端（768px 至 1023px）

- 侧边栏折叠为图标栏。
- 邮件列表与详情二选一显示，保留明确返回路径。

### 移动端（< 768px）

- 单栏导航。
- 写信 Dialog 和邮件详情适配为单栏、接近全屏的移动布局。
- 底部导航最多 4 项：收件箱、已发送、全部邮件、设置。
- 主操作按钮和输入框最小高度 44px。

- 选中状态不能只靠颜色，必须同时有背景、字重或图标变化。
- 深色模式单独设计，不直接反转亮色值。

## 5. 字体与排版

字体栈：

```css
font-family: "MiSans", "HarmonyOS Sans SC", "Aptos",
  "PingFang SC", "Microsoft YaHei", sans-serif;
```

- 页面标题：24/32，600。
- 区块标题：16/24，600。
- 正文：14/22（桌面）或 16/24（移动端）。
- 辅助文字：13/20，不小于 12px。
- 邮箱地址与验证码可使用等宽数字特性，但不强制使用等宽字体。
- 长地址默认换行；仅列表行可以省略，并提供 Tooltip 查看完整内容。

## 6. 空间、圆角和阴影

- 使用 4px 基础网格：4、8、12、16、24、32、48。
- 页面边距：移动端 16px，平板 24px，桌面 32px。
- 输入框和按钮圆角：10px。
- 卡片和 Dialog 圆角：14px。
- 页面结构优先使用 1px 边框分层，避免每张卡片都有阴影。
- 浮层阴影：`0 18px 48px rgba(15, 23, 42, .16)`。

## 7. 核心组件规范

### Button

- 每个视图仅一个主按钮。
- 默认高度 40px，移动端关键按钮 44px。
- loading 时保持原宽度、禁用重复提交并显示 Spinner。
- 图标按钮必须有 Tooltip 和 `aria-label`。

### Field / Input

- 永远显示 Label，不能只依赖 placeholder。
- 错误紧贴字段下方，说明原因与修复方式。
- blur 后校验；提交失败时聚焦第一个错误字段。
- 密码输入提供显示/隐藏切换和正确的 `autocomplete`。

### Select / Combobox

- 支持键盘选择与搜索。
- 域名选择展示完整域名，必要时同时显示状态标签。
- 最近项目与全部项目分组显示，不用 hover 才暴露关键信息。

### Dialog / Sheet

- 桌面使用 Dialog，移动端转为全屏 Sheet。
- 有未保存内容时关闭必须二次确认。
- 打开后焦点进入第一个有效输入，关闭后焦点返回触发按钮。

### Toast

- 成功提示 3 秒自动消失；失败提示保留恢复动作。
- 使用 `aria-live="polite"`，不能抢走输入焦点。

## 8. 动效

- 普通状态变化：160ms 至 220ms。
- Dialog/Sheet：220ms 至 280ms。
- 只动画 `opacity` 和 `transform`。
- 动效表达层级和因果，不使用页面视差或装饰性循环动画。
- 完整支持 `prefers-reduced-motion`。

## 9. 无障碍与响应式验收

- 所有操作可仅使用键盘完成。
- 焦点环始终可见，不能用 `outline: none` 直接移除。
- 点击目标至少 44×44px，图标之间至少 8px。
- 375、768、1024、1440px 四档均不得产生横向滚动。
- 页面切换后将焦点移动到主内容标题。
- 错误、成功、未读、选中状态均不能只靠颜色表示。

## 10. 禁止模式

- 不使用 Emoji 作为功能图标。
- 不使用大面积渐变、视差滚动、发光描边或过强玻璃效果。
- 不保留“邮箱地址既是登录身份又是邮箱账户”的耦合。
- 不要求用户先创建邮箱账户，才能使用已授权域名的任意前缀发信。
- 不以 `accountId` 作为新版写信功能的必填发件身份。
