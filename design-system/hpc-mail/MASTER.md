# HPC Mail React 设计系统

> 本文件是 React 重构的唯一全局设计基线。实现页面前必须先读本文件，再读 `pages/<page>.md`；页面文件只覆盖页面特例。旧版框架、组件库和编辑器不进入新架构。

## 1. 产品定义

HPC Mail 是“平台账户 + 多邮箱 + 多域名”的邮件生产力工具，同时包含权限化管理后台。它不是单邮箱客户端，也不是营销型 SaaS 模板。

核心语义：

- **平台账户**：用户名、显示名称、密码、语言和偏好；不等于任何邮箱地址。
- **邮箱**：平台账户有权管理的收件地址，可有零个或多个。
- **域名**：平台配置且角色授权的邮件后缀。
- **发件地址**：合法前缀与已授权域名的组合；无需预先创建为邮箱。
- **默认收件箱**：当前用户全部邮箱的邮件合集；邮箱只是筛选条件。

设计原则按优先级排序：

1. 内容与任务优先：邮件、发件、筛选和管理操作永远先于装饰。
2. 速度可感知：首个操作反馈不超过 100ms，列表不因异步数据跳动。
3. 语义清楚：平台账户、邮箱、域名、发件地址不得混用。
4. 桌面高效率、移动端功能完整：移动端重排，不阉割核心能力。
5. 安静可靠：不使用毛玻璃、渐变、发光、海报式登录、装饰性大卡片。

## 2. React 技术与组件基线

- React 19 + TypeScript，组件使用函数组件与显式 Props 类型。
- Tailwind CSS 4，使用 CSS-first `@theme` 与语义 CSS 变量；业务 JSX 禁止散落任意色值。
- `components/ui` 保存项目自有的 shadcn-style 源码组件，不依赖不可修改的黑盒 UI 套件。
- Radix Primitives 提供 Dialog、Sheet、DropdownMenu、Popover、Select、Tabs、Tooltip、Toast 等可访问性基础。
- Lucide React 是唯一功能图标集，默认 `strokeWidth={1.8}`；禁止 Emoji 充当结构图标。
- 表格、查询、虚拟列表可以使用 TanStack 系列能力，但外观、空状态和键盘行为必须遵守本规范。
- 路由页面按功能拆包；邮件正文渲染、富文本编辑器和管理图表延迟加载。
- 不保留任何旧版框架、旧组件库或旧编辑器的视觉兼容层。

推荐目录：

```text
src/
├─ app/                 # Provider、路由、权限与错误边界
├─ components/ui/       # 项目拥有的基础组件
├─ components/mail/     # MailboxFilter、MessageRow、MailBody 等
├─ components/admin/    # DataTable、Metric、PermissionGate 等
├─ features/            # auth、inbox、compose、settings、admin
├─ hooks/               # 快捷键、媒体查询、焦点恢复
├─ lib/                 # API、格式化、安全净化、校验
└─ styles/              # Tailwind 入口、主题和打印样式
```

## 3. 视觉方向与反模式

视觉风格：Flat Design + Minimalism + 适度高密度。浅灰蓝背景、近白表面、深墨色文本、一个可信蓝强调色；红、绿、琥珀仅表达语义状态。

必须避免：

- 紫蓝渐变、毛玻璃、霓虹描边、超大圆角和无意义阴影。
- 海报式登录、超大标题、插画占据首屏。
- 所有内容都装进卡片，或卡片嵌套卡片。
- 以等宽字体制造“技术感”；API 密钥片段与验证码除外。
- 同一层级混用填充/描边图标、任意尺寸图标或 Emoji。
- 为了动画阻塞导航，或在邮件列表逐行播放入场动画。

## 4. Design Tokens

### 4.1 颜色

使用 OKLCH 定义基础色，组件只引用右侧语义 Token。禁止纯黑和纯白。

HPC Mail 当前只提供浅色主题，不保留旧主题兼容层。具体 Token 以 `mail-react/src/styles/index.css` 为准：浅灰蓝画布、近白表面、深墨色文字、可信蓝主色，成功/警告/危险色只表达状态。

规则：

- 正文与背景对比度至少 4.5:1；大文本和 UI 图形至少 3:1。
- 选中、未读、成功、失败必须同时提供文字/字重/图标，不能只改变颜色。
- 即使操作系统处于深色模式，应用也保持浅色，并向浏览器声明 `color-scheme: light`。
- 邮件 HTML 正文保持邮件自身颜色，但阅读器工具条始终使用应用 Token。

### 4.2 字体

```css
--font-sans: "Noto Sans SC", "MiSans", "HarmonyOS Sans SC",
  "PingFang SC", "Microsoft YaHei", sans-serif;
--font-mono: "SFMono-Regular", "Cascadia Code", "Noto Sans Mono", monospace;
```

- Noto Sans SC 仅加载 400/500/600/700，优先自托管中文子集，`font-display: swap`。
- 主标题 `24/32 600`；页面副标题 `18/28 600`；区块标题 `16/24 600`。
- 桌面正文 `14/22 400`；移动正文 `16/24 400`；辅助文字 `13/20 400`，不得低于 12px。
- 按钮/标签 `14/20 600`；数据列启用 `font-variant-numeric: tabular-nums`。
- 邮件地址允许换行；列表中省略时必须提供可访问的完整值。

### 4.3 空间与尺寸

| Token | 值 | 典型用途 |
| --- | --- | --- |
| `--space-1` | 4px | 图标内部间距 |
| `--space-2` | 8px | 紧密控件间距 |
| `--space-3` | 12px | 行内分组 |
| `--space-4` | 16px | 页面移动边距 |
| `--space-5` | 20px | 工具栏 |
| `--space-6` | 24px | 区块间距 |
| `--space-8` | 32px | 页面桌面边距 |
| `--space-12` | 48px | 大区块分隔 |

- 控件高度：紧凑 36px、默认 40px、触屏 44px。
- 邮件列表行：紧凑 56px、默认 68px、舒适 80px；同页只能使用一种密度。
- 图标视觉尺寸：16/18/20/24px；图标按钮点击区域始终不小于 44×44px。
- 页面 gutter：移动 16px、平板 24px、桌面 32px。

### 4.4 圆角、边框、阴影

```text
radius-sm      6px    行内标签、小状态
radius-control 8px    输入、按钮、菜单项
radius-panel   12px   Dialog、Sheet、独立面板
radius-round   999px  头像、计数徽标（仅胶囊语义）
border         1px solid var(--color-border)
shadow-popover 0 12px 32px oklch(18% .03 253 / .14)
shadow-modal   0 24px 64px oklch(18% .03 253 / .20)
```

页面分区优先使用边框与表面差异；普通卡片不加阴影。只有 Popover、Dropdown、Dialog、Toast 使用阴影。

### 4.5 动效与层级

```text
motion-instant 100ms
motion-fast    140ms
motion-base    200ms
motion-slow    260ms
ease-out       cubic-bezier(.25, 1, .5, 1)
ease-in        cubic-bezier(.5, 0, .75, 0)
z-base 0 / z-sticky 20 / z-dropdown 40 / z-overlay 60 /
z-modal 70 / z-toast 80 / z-tooltip 90
```

- 只动画 `opacity` 与 `transform`；退出时长为进入的约 70%。
- 列表筛选直接交叉淡化，不做逐项飞入。
- `prefers-reduced-motion: reduce` 下停用位移，仅保留必要的即时状态更新。

## 5. 响应式应用外壳

断点用于行为变化，不按设备品牌命名：

| 范围 | 导航 | 内容结构 |
| --- | --- | --- |
| `< 768px` | 底部导航，最多 4 项 | 单栏；列表、详情、设置独立路由 |
| `768–1023px` | 72px 图标侧栏 | 列表/详情二选一；Sheet 承载筛选 |
| `1024–1279px` | 188px 侧栏 | 单一宽工作区，列表/详情使用独立路由 |
| `≥ 1280px` | 188px 侧栏 | 单一宽工作区，内容最大宽度 1480px |

桌面邮件结构：

```text
┌──────────────┬─────────────────────────────────────────────────────┐
│ 主导航 188   │ 全部收件 / 邮箱筛选 / 邮件列表                      │
└──────────────┴─────────────────────────────────────────────────────┘
```

- 侧栏只放一级目的地，不列出所有邮箱；邮箱在收件箱工具栏作为可搜索筛选器。
- 管理页复用侧栏，但主区为单一工作区，不保留空邮件列表列。
- 移动底部导航为：收件箱、已发送、写邮件、设置；管理入口放在平台账户菜单并按权限展示。
- 固定栏必须为滚动内容预留高度，并加入 `env(safe-area-inset-*)`。
- 320px 是最低可操作宽度；375、768、1024、1440px 是强制验收点。

## 6. 核心组件契约

### Button / IconButton

- Variant：`primary`、`secondary`、`ghost`、`danger`；每个视图最多一个 `primary`。
- 必须覆盖 default、hover、focus-visible、active、disabled、loading、success/error feedback。
- loading 保持原宽度，设置 `disabled` 与 `aria-busy`；禁止重复提交。
- IconButton 必须有 `aria-label`，桌面 hover/focus 显示 Tooltip。

### Field / Input / Textarea

- 永远显示 `<label>`；placeholder 只给示例。
- blur 后校验，错误紧贴字段并用 `aria-describedby` + `role="alert"` 关联。
- 提交失败后聚焦首个错误；错误时保留用户输入。
- 密码支持显示/隐藏、正确 `autocomplete`，移动输入使用合适 `inputMode`。

### Select / Combobox / MailboxFilter

- 超过 8 项使用可搜索 Combobox；域名与邮箱均展示完整地址及状态。
- MailboxFilter 默认值是“全部邮箱”，显示筛选结果数量，支持清除。
- 触发器必须暴露 `aria-expanded`、`aria-controls`；选项使用 roving focus。

### Toolbar

- 主操作靠近内容起点或末端，不居中漂浮。
- 宽度不足时，保留返回、标题、主操作，其余进入“更多”菜单。
- 键盘焦点顺序与视觉顺序一致；sticky 时不得遮挡页面标题。

### MessageRow

- 整行是可聚焦的详情入口；内部星标/选择框是独立按钮，不嵌套交互元素。
- 未读使用字重 + 未读点 + 可访问文本；选中使用背景 + 左侧 2px 指示 + `aria-selected`。
- 发件人、主题、摘要、时间形成固定层级；长地址省略但保留 accessible name。

### DataTable

- 表头使用真实 `<th>`，排序使用 `aria-sort`；批量选择有全选说明。
- 小屏不强行横向压缩：关键列重排为列表行，次要列进入详情抽屉。
- 加载使用固定行高骨架；空、错误、无权限分别处理。

### Dialog / Sheet / AlertDialog

- Dialog 仅用于短期任务；移动端转为全高 Sheet。主导航流程使用路由，不用弹窗。
- 打开后聚焦标题或首个字段，关闭后返回触发器；Esc 可关闭非破坏性流程。
- 未保存内容关闭前确认；破坏性操作使用 AlertDialog 并写明对象与后果。

### Toast / Banner

- Toast 不抢焦点，`aria-live="polite"`；成功 3 秒，错误保留恢复动作。
- 页面级错误使用 Banner 或就地 ErrorState，不把所有错误都做成 Toast。

## 7. 通用状态模型

| 状态 | 视觉 | 行为与文案 |
| --- | --- | --- |
| 初始加载 `<300ms` | 保留结构，不闪 Spinner | 等待数据，避免闪烁 |
| 加载 `≥300ms` | 与真实布局同尺寸的骨架 | `aria-busy="true"`，不反复播报 |
| 增量加载 | 列表尾部 2–3 行骨架 | 已有内容保持可操作 |
| 空数据 | 简洁图标 + 原因 + 一个动作 | 说明“这里会出现什么” |
| 筛选无结果 | 当前筛选摘要 + 清除筛选 | 不使用“暂无数据”笼统文案 |
| 网络错误 | 原因 + 重试 | 保留筛选、草稿和输入 |
| 无权限 | 锁图标 + 权限说明 | 提供返回，不静默隐藏当前深链路 |
| 401 | 清理会话并返回登录 | 登录后尽可能恢复原路由 |
| 429 | 显示等待时间 | 禁用重复请求，允许稍后重试 |
| 成功 | 就地更新 + 简短 Toast | 破坏操作尽可能提供撤销 |

错误文案格式：**发生了什么 + 为什么（已知时）+ 下一步**。禁止只写“操作失败”。

## 8. 键盘与焦点

全局快捷键仅在焦点不位于输入/编辑器时生效，并提供设置开关与快捷键帮助：

| 快捷键 | 行为 |
| --- | --- |
| `/` | 聚焦当前页面搜索 |
| `c` | 打开写邮件 |
| `g` 后 `i` | 前往收件箱 |
| `j` / `k` | 下一封 / 上一封邮件 |
| `Enter` | 打开聚焦邮件 |
| `s` | 切换星标 |
| `r` | 回复当前邮件 |
| `f` | 转发当前邮件 |
| `Esc` | 关闭浮层或返回邮件列表 |
| `Ctrl/Cmd + Enter` | 写信确认发送 |

- 路由切换后聚焦主标题或 `main`，返回列表时恢复原邮件行和滚动位置。
- 提供“跳到主要内容”链接。
- 不覆盖浏览器、系统和辅助技术保留快捷键；快捷键提示同时显示 Windows/macOS 写法。

## 9. 无障碍基线

- 目标 WCAG 2.2 AA；支持键盘、屏幕阅读器、200% 页面缩放与 400% 文本重排。
- 所有可点击区域使用 button/a 等原生语义；禁止用 div 模拟按钮。
- 标题按 h1→h2→h3 顺序；页面只有一个 h1。
- 动态数量、保存状态、发送结果使用合适的 `aria-live`，不制造重复播报。
- 焦点环 2px，距元素 2px；不可仅因鼠标样式而移除。
- 触控目标至少 44×44px，相邻目标至少 8px。
- 图标隐藏于辅助树或拥有明确名称；装饰图片空 alt。
- 颜色之外必须有文字、形状或图标；图表同时提供数据表与文字摘要。

## 10. 性能与体验预算

- LCP < 2.5s、INP < 200ms、CLS < .1；首屏应用壳不得依赖大图或远程字体完成后才显示。
- 50 条以上邮件启用虚拟列表；分页/游标加载不得重置滚动。
- 搜索输入 200–300ms debounce，并可取消旧请求。
- 列表行避免订阅整个全局 Store；使用稳定 key 与实测 Profiler 数据决定 memo。
- 邮件远程图片预留尺寸，首屏正文图片可 eager，其余 lazy；加载失败不改变操作栏位置。
- 路由 ErrorBoundary 隔离错误；单封恶意/损坏邮件不能拖垮整个应用。

## 11. 简体中文 UX 文案

- 使用“平台账户 / 邮箱 / 域名 / 发件地址”，禁止以“账号邮箱”代指身份。
- 按钮采用动词 + 对象：`保存设置`、`创建密钥`、`发送邮件`、`清除筛选`。
- 时间与数量使用 `Intl.DateTimeFormat('zh-CN')`、`Intl.NumberFormat('zh-CN')`。
- 中英文切换预留至少 35% 横向空间；地址、密钥、错误 ID 允许断行与复制。
- 危险确认写明对象：`吊销密钥“自动报表”？吊销后无法恢复。`

## 12. 全站验收清单

- [ ] 320/375/768/1024/1440px 无页面级横向滚动。
- [ ] 桌面邮件页是单一宽工作区，移动端是单栏并有不超过 4 项底部导航。
- [ ] 收件箱默认展示用户全部邮箱的邮件，邮箱只作为筛选器。
- [ ] 平台账户资料不展示或依赖某个默认邮箱。
- [ ] 所有核心任务可只用键盘完成，返回后恢复焦点和滚动。
- [ ] 浅色主题下文字、边框、焦点和状态均达到对比度要求；系统深色偏好不会改变界面。
- [ ] reduced-motion 下无非必要位移；200% 缩放不遮挡操作。
- [ ] 加载、空、无结果、错误、无权限、离线均有明确恢复路径。
- [ ] 页面不存在毛玻璃、渐变、海报式登录、卡片套卡片和任意 z-index。
- [ ] React、Tailwind、Radix/shadcn-style 组件职责清晰，无旧版兼容代码。
