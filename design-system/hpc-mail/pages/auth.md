# Authentication Page

## 页面目标

登录身份与邮箱地址彻底解耦。用户使用全局唯一的用户名和密码登录；一个用户可以管理多个域名、固定邮箱与临时发件地址。

## 登录表单

字段：

1. 用户名：`autocomplete="username"`，支持粘贴，大小写不敏感。
2. 密码：`autocomplete="current-password"`，提供显示/隐藏按钮。

交互：

- Enter 提交。
- 提交中按钮保持宽度并显示 Spinner。
- 错误显示在对应字段下方；用户名不存在时统一返回“用户名或密码错误”，避免账户枚举。
- 迁移阶段允许旧邮箱登录，但 UI 不再要求选择域名；输入包含 `@` 时走兼容解析。

## 注册表单

字段：

1. 用户名。
2. 密码。
3. 确认密码。
4. 注册码：仅在系统设置为必填或可选时显示。
5. Turnstile：仅在后端设置要求时显示。

注册页不出现邮箱前缀或域名选择器，也不自动创建 `username@某域名`。

注册成功后：

- 直接进入应用。
- 如果用户没有任何固定邮箱，显示非阻塞式引导：“添加常用邮箱”或“稍后再说”。
- 用户的可用域名来自角色/注册码授权，不来自注册时选择的某个邮箱。

## 用户名规则

- 长度 3 至 32。
- 允许字母、数字、点、下划线和短横线。
- 大小写不敏感，保存时保留用户输入的展示形式。
- 不允许首尾为点或连续两个点。
- 保留 `admin`、`root`、`system` 等名称时由后端配置控制。

## 组件映射

- `Tabs`：登录 / 注册（仅注册开放时展示注册入口）。
- `Field`、`InputGroup`：用户名和密码。
- `Button`、`Spinner`：提交状态。
- `Alert`：全局服务错误。
- `Tooltip`：密码可见性图标说明。
- `Dialog`：OAuth 后补充资料；普通注册不使用弹窗。

## 页面专属视觉

- 背景使用 `--background`，认证卡片使用 `--surface`。
- 桌面品牌区域允许使用非常淡的网格纹理，但不得影响文字对比度。
- 主按钮使用 `--primary`，注册链接使用普通文本按钮。
- 页面只出现一个主操作。

## 验收条件

- 登录和注册表单中完全不需要选择邮件域名。
- 用户可在不创建任何邮箱地址的情况下拥有登录身份。
- 旧管理员数据迁移后仍可登录。
- 375px 宽度下无横向滚动，软键盘弹出时提交按钮可见。
- 错误可被屏幕阅读器读出，Tab 顺序与视觉顺序一致。
