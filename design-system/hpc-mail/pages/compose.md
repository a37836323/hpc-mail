# Compose Page

## 页面目标

用户可以使用任意合法前缀与任意已配置、已授权的域名组合发件地址，不需要预先创建邮箱账户。

## 桌面布局

```text

│ 写邮件                                                最小化  ×      │
├──────────────────────────────────────────────────────────────────────┤

│                            billing@hpc.email                         │
│                                                                      │

├──────────────────────────────────────────────────────────────────────┤
│ 回形针  清空正文                         已自动保存  删除草稿  [发送] │
└──────────────────────────────────────────────────────────────────────┘
```

- 桌面以大型 Reka Dialog 打开。
- 移动端将同一 Dialog 适配为接近全屏的编辑界面，底部操作区尊重安全区。
- 发件人区始终可见，不隐藏在二级菜单中。

## 发件人控件

由三个独立值组成：

1. 显示名称 `name`：可选，默认沿用上一次值。
2. 前缀 `localPart`：必填，可输入任意合法邮箱 local-part。
3. 域名 `domain`：必填，只能从当前用户已授权的配置域名中选择。

交互：

- 输入前缀时，下方实时展示最终地址，如 `alerts@option.red`。
- 最近地址使用独立下拉框，域名使用只包含已授权域名的原生 Select。
- 最近使用的完整发件地址可一键填入，但它只是历史记录，不是必须创建的 Account。
- 前缀和域名在 blur 后分别校验，服务端再次完整校验。
- 前缀包含非法字符、以点开头/结尾、连续两个点或超过 64 字符时给出明确错误。
- 回复邮件时，优先使用原始收件地址 `toEmail` 作为发件地址；无权限时回退到最近使用地址并明确提示。

## 收件人和正文

- To 使用 Element Plus `InputTag`，支持逗号、分号、空格和回车批量录入。
- 当前发送 API 只提供 To；本轮未虚构尚不存在的 Cc/Bcc 能力。
- 主题是单行输入；正文继续使用现有 TinyMCE 封装。
- 附件以带文件名、大小、上传状态的 Item 展示。
- 草稿 2 秒防抖自动保存；离线时保存在 Dexie，恢复网络后同步。

## 发送交互

- `Ctrl/Cmd + Enter` 可发送。
- 发送按钮提交中不可重复点击，并展示上传/发送阶段。
- 成功后关闭编辑器并提供“查看已发送”动作。
- 失败后保留全部内容，错误提示必须给出重试或修复路径。
- 删除草稿属于危险操作，放在最右侧并二次确认。

## 组件映射

- Reka `Dialog`：桌面与移动容器。
- 项目内 `FormField`、`AppButton`、`IconButton`：字段与操作。
- 原生 `select`：域名和最近发件地址。
- Element Plus `InputTag`：To 收件人。
- `TinyEditor`：现有 TinyMCE 正文编辑器封装。
- 自定义附件 Item 与现有消息反馈：附件、草稿和发送状态。

## 页面专属视觉

- 编辑器以边框分区，不使用多层卡片。
- 发件地址预览使用 13px `--muted-foreground`，验证通过后显示 Check 图标和“可发送”。
- 操作区位于 Dialog 底部，移动端布局使用安全区间距。
- 除“发送”外，其余操作均为 secondary/ghost。

## 验收条件

- 用户不添加 Account 也能从 `任意合法前缀@已授权域名` 发信。
- 前端不能提交未配置域名，后端不能信任前端提交的完整 `from` 地址。
- 动态发件记录会出现在统一“已发送”列表中。
- 从 Catch-all 地址收到的邮件点击回复时，默认使用该原始收件地址发件。
- 草稿在 Dexie 中防抖保存；发送失败会保留正文与附件元数据。
- 键盘、触屏和 375px 移动端均可完成完整写信流程。
