# 登录 / 注册

> 继承 `../MASTER.md`。本页目标是让用户在几秒内完成平台账户认证，不承担产品宣传任务。

## 1. 页面目标与语义

- 只使用平台用户名和密码登录，不接受邮箱地址作为兼容身份。
- 登录表单不预填、硬编码或在 placeholder 中展示任何真实用户名。
- 注册只创建平台账户，不自动创建 `username@domain` 邮箱。
- 登录后跳转原目标路由；无原目标时进入 `/inbox`。

## 2. 布局

### 桌面 `≥768px`

```text
┌──────────────────────────────────────────────────────────────┐
│  HPC Mail                                                    │
│                                                              │
│                  欢迎回来                                    │
│                  使用用户名登录 HPC Mail                     │
│                  用户名 [                  ]                 │
│                  密码   [                显示]               │
│                  [          登录          ]                 │
│                  没有账户？创建账户                         │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

- 表单列宽 `min(400px, calc(100vw - 32px))`，位于视觉中心略偏上。
- Logo 位于页面左上或表单顶部，二者择一；不做左侧海报、卖点墙或插画轮播。
- 背景只使用 `--color-canvas`，表单与背景通过间距建立层级；不强制包卡片。

### 移动 `<768px`

- 单栏，水平 gutter 16px；表单宽度 100%。
- 顶部留白 `clamp(32px, 10dvh, 72px)`，不得把提交按钮推到软键盘下方。
- 页面最小高度使用 `100dvh`，底部加入安全区。

## 3. 组件与内容

- `AuthShell`：Logo、语言切换、主内容。
- `Tabs` 或文本链接：登录/注册；注册关闭时不渲染无效 Tab。
- `Field`：可见 Label、Input、Helper/Error。
- `PasswordField`：显示/隐藏按钮，按钮有 `aria-label`。
- `Button`：全宽主按钮；提交中保持宽度。
- `Alert`：仅承载服务不可用等跨字段错误。

字段：

| 字段 | 属性 | 规则 |
| --- | --- | --- |
| 用户名 | `autocomplete="username"`、`autocapitalize="none"` | 3–32 字符；错误不枚举账户 |
| 密码 | `autocomplete="current-password"` | 支持粘贴与密码管理器 |
| 注册确认密码 | `autocomplete="new-password"` | blur 或提交时比较 |
| 注册密钥 | `autocomplete="off"` | 仅系统要求时显示 |

禁止：邮箱字段、域名选择器、“兼容旧邮箱登录”文案、真实凭据示例、禁用粘贴。

## 4. 交互与状态

- 初始焦点进入用户名；如果用户名由浏览器自动填充，则进入密码。
- Enter 提交；密码可见性按钮不触发表单提交。
- 首次提交后才展示必填错误；服务端错误保留所有非密码字段。
- 提交中按钮显示 Spinner、`aria-busy` 且禁用重复提交。
- 凭据错误统一为：“用户名或密码不正确，请重新输入。”
- 网络错误：“暂时无法连接服务器。请检查网络后重试。”并提供 `重试登录`。
- 连续失败不得在前端泄露限流策略；429 显示可重试时间。
- 登录成功不播放庆祝动画，立即进入目标页面。

## 5. 注册

- 字段顺序：用户名、密码、确认密码、按配置出现的注册密钥/人机验证。
- 密码要求在输入前持续可见，不在失败后突然出现。
- 注册成功直接建立会话；无邮箱用户进入统一收件箱空状态，可选择“添加邮箱”或“稍后设置”。
- 注册失败聚焦第一个无效字段，错误使用 `role="alert"`。

## 6. 无障碍与键盘

- 页面 h1 为“登录”或“创建账户”，Logo 不是标题。
- Tab 顺序：语言 → 用户名 → 密码 → 显示密码 → 主按钮 → 模式切换。
- 200% 缩放时表单不裁切；错误换行后不覆盖下一字段。
- 焦点环、错误图标与错误文字同时出现；不以红框作为唯一提示。
- 浏览器自动填充样式必须保持文字可读。

## 7. 验收

- [ ] 页面无海报区、背景大图、渐变、毛玻璃与真实账号名称。
- [ ] 用户名/密码视觉居中但文案和字段左对齐。
- [ ] 320×568 和软键盘场景可完成提交，无横向滚动。
- [ ] 仅用户名可登录；平台账户创建不依赖邮箱。
- [ ] 错误可恢复、可读出，输入不会无故清空。
